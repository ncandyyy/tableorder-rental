# 상담 신청 → 구글 시트 + 슬랙 연결 방법

웹사이트 폼 → **Google Apps Script(웹 앱)** → ① 구글 시트에 한 줄 저장 ② 슬랙 채널에 알림

**토스 렌탈·네이버 커넥트·포스기 렌탈과 같은 시트·같은 웹 앱 주소를 함께 씁니다.** 신청서에 페이지 이름표(`page`)가 같이 오기 때문에
페이지마다 다른 탭에 쌓이고, 상단 바 누적 조회수도 따로 셉니다.

| 페이지 | `page` 값 | 신청이 쌓이는 탭 | 누적 조회수 (스크립트 속성) | 슬랙 웹훅 (스크립트 속성) |
| --- | --- | --- | --- | --- |
| 토스 렌탈 | 없음 | `토스 신청목록` | `VIEW_COUNT` | `SLACK_WEBHOOK_URL` |
| 네이버 커넥트 | `connect` | `커넥트 신청목록` | `VIEW_COUNT_CONNECT` | `SLACK_WEBHOOK_URL_CONNECT` |
| 포스기 렌탈 | `poss` | `포스기 신청목록` | `VIEW_COUNT_POSS` | `SLACK_WEBHOOK_URL_POSS` |
| **테이블오더 렌탈 (이 페이지)** | `torder` | `테이블오더 신청목록` | `VIEW_COUNT_TORDER` | `SLACK_WEBHOOK_URL_TORDER` |

- 다른 페이지 사이트는 고칠 것이 없습니다. 다른 탭의 열 구성도 그대로입니다.
- 이 페이지만 **`신청 테이블오더`** 열(업오더 / 하이오더 / 티오더)이 `매장 상태` 바로 뒤에 하나 더 있습니다.
- [`apps-script/Code.gs`](../apps-script/Code.gs) 는 poss-rental 의 공용 코드에 `torder` 한 묶음, 페이지별 추가 항목(`extra`) 처리, `testSubmitTorder` 를 더한 것입니다.

> 사이트의 접수 주소(`FORM_ENDPOINT`)는 이미 공용 주소로 들어가 있습니다.
> 아래 2단계(새 버전 배포)를 하기 전까지는 테이블오더 신청이 **토스 신청목록 탭 + 토스 알림**으로 들어갑니다. (빠지지는 않습니다)

---

## 1. 슬랙: 테이블오더 전용 워크플로 만들기

1. 슬랙 워크플로 빌더에서 기존 포스기(또는 커넥트) 워크플로를 복제합니다.
2. 이름을 예: `테이블오더_웹페이지 렌탈 접수` 로 바꾸고
   - 상품 문구 → `[테이블오더]`
   - 사이트 주소 → `https://tableorder-rental.netlify.app/` (실제 도메인이 다르면 그 주소)
   - **텍스트 변수 `tableOrder` 를 추가**하고 메시지에 넣기 (예: `신청 테이블오더: {tableOrder}`)
3. 게시하고, 웹훅 주소(`https://hooks.slack.com/triggers/...`)를 복사 — 코드·저장소에 넣지 말고 2단계 스크립트 속성에만 넣습니다.

## 2. 구글: 공용 시트의 Apps Script 업데이트

1. 공용 신청 시트 → **확장 프로그램 → Apps Script**
2. 이 저장소의 [`apps-script/Code.gs`](../apps-script/Code.gs) 내용으로 통째로 바꾸고 저장
   (시트 쪽 코드를 따로 고친 적이 있다면 통째로 바꾸지 말고 `torder` 묶음·`headersFor_`·`buildRow_`·`notifySlack_` 변경분만 옮기세요)
3. **프로젝트 설정 → 스크립트 속성 → 속성 추가**: `SLACK_WEBHOOK_URL_TORDER` = 1단계 웹훅 주소
4. 함수 `setup` 실행 → `테이블오더 신청목록` 탭이 머리글과 함께 생깁니다 (기존 탭은 그대로)
5. `testSubmitTorder` 실행 → 탭에 테스트 한 줄 + 슬랙 알림이 오면 성공 (테스트 행은 지우세요)
6. **배포 → 배포 관리 → (연필) 수정 → 버전: 새 버전 → 배포**
   - ⚠ "새 배포"가 아니라 기존 배포를 **수정**해야 웹 앱 주소가 그대로 유지됩니다. (주소가 바뀌면 다른 사이트 신청이 끊깁니다)
7. 확인: 웹 앱 주소를 브라우저로 열어 `"pages":["toss","connect","poss","torder"]` 가 보이면 적용된 것입니다.

> `SLACK_WEBHOOK_URL_TORDER` 를 넣지 않으면 기본(토스) 워크플로로 알림이 갑니다. 이때는 그 워크플로에 없는 `tableOrder` 변수는 보내지 않습니다(알림 실패 방지). 시트에는 항상 기록됩니다.

## 3. 확인

실제 사이트에서 테스트 신청 한 건 → `테이블오더 신청목록` 탭과 슬랙 알림을 확인하세요.

워크플로 변수 (모두 텍스트)

| 변수 | 내용 | 예 |
| --- | --- | --- |
| `receivedAt` | 접수일시 | 2026-11-18 10:31:05 |
| `storeStatus` | 매장 상태 | 매장 운영 중 |
| `tableOrder` | 신청 테이블오더 (이 페이지 전용 워크플로만) | 티오더 |
| `industry` | 업종 | 음식점 |
| `phone` | 휴대폰 | 010-1234-5678 |
| `contactDay` | 연락 희망일 (요일) | 월요일 |
| `contactDate` | 연락 희망일 (날짜) | 2026-11-23 |
| `contactTime` | 연락 희망 시간 | 오후 14시 |
